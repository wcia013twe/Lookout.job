# Complete recorded application view in Documents

- Replaced the resume-first Documents layout with a readable application preview: all recorded field answers, completeness counts, resume metadata, missing-answer labels and current contact/background reference in draft mode.
- Historical states default to the latest available attempt snapshot. Current draft/profile references stay separate; immutable recorded answers are never backfilled from today’s profile. Confirmed and uncertain outcomes use the shared submission-record model.
- Reused the existing owner-scoped record read when Documents opens, including loading/error retry. Recorded-resume download reuses the existing ownership-checked handler; detailed submission evidence remains expandable.
- Preserved the original draft editor and save/review/approval handlers behind Edit draft & review. Overview, Prep and Rounds & email retain their existing behavior. No live employer form is fetched, no missing fact is invented and previewing grants no approval.
- Demo coverage: captured fictional name/email distinct from the current profile, a filled attempt, an unanswered draft question, uncertain attempt and saved role without a draft. Demo actions remain disabled and account data stays isolated.
- Validation: 436 tests, frontend typecheck, data validation (147 roles), production static build, whitespace check and mocked desktop-dark/mobile-light browser checks. Browser coverage includes every recorded field, draft/snapshot separation, completeness, missing/uncertain/no-draft states, source switching, collapsed editor, disabled approval/save, navigation and overflow.
- Existing MCP read_application_record and draft/approval boundaries are unchanged. No migrations, gateway version or deployment capabilities changed. Real account reads, private downloads and live employer forms were not exercised. The pre-existing Next.js dependency advisory remains outside this UI pass.
