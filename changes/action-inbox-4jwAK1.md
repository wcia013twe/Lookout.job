# Durable Action Board inbox

- Application and submission-attempt transitions now append owner-private handoffs in the same database transaction. One pending entry per application prevents duplicate reports; changed conditions preserve superseded history and resolved entries remain visible. Existing blockers/reviews/stalled attempts are backfilled.
- The Action Board reads the durable inbox, retains action history, and uses a one-time timer for five-minute stalled-submission checks. Existing exact-version approval and human negative-outcome recovery resolve their conditions. A signed-in human reporting Submitted closes attention as user-reported while retaining the uncertain attempt and duplicate-execution block; agent status changes cannot clear it or fabricate receipts.
- Replaced idle 15-second workspace polling with an owner-scoped Realtime subscription to a minimal workspace version record. Reconnect, focus and online events reconcile missed changes; error retries and local edit protection remain. Interview/learning preparation changes also invalidate snapshots. Subscriptions stop on account change and demo suspension.
- MCP parity: new read-only `read_action_inbox` → `applications.inbox.read` uses `workspace:read` and the same owned paginated reader as browser `read_action_inbox`. Existing domain writes maintain the inbox; no clear/dismiss or consent shortcut exists. Node delegates lightweight reads to Edge. Developer contract advanced from 70 to 71.
- Demo: fictional completed tasks remain visible in Action history, uncertain tasks stay pending until resolved, and Reset task preview restores them. Desktop/mobile browser verification blocks all external traffic and checks notes, resolution, retained history, reset, overflow and page errors.
- Validation: `npm test -- --test-concurrency=2` passed all 730 tests, including every database scenario, real Node HTTP MCP → Edge boundary → migrated SQL integration, migration backfill/publication registration, scope audit, rollback/dedup, owner isolation, approval and uncertainty handling, reconnect and idle-sync checks. `npx --prefix next-app tsc --noEmit -p next-app/tsconfig.json`, `npm run build`, `npm run validate:data` (158 roles), `git diff --check`, and `node scripts/check-action-inbox-ui.mjs` passed.
- Limits: SQL tests use disposable PGlite databases; the Edge HTTP boundary is an in-process adapter around the real SQL/validation contract. Realtime subscription lifecycle is tested with callback fixtures and publication membership is tested in SQL; no live hosted WebSocket delivery, remote deployment, real consent or employer submission was performed. Release the migration before gateway/MCP developer contract 71 and frontend. Inbox resolution does not wake a runner. The existing local Docker stack was inspected only and not modified.
