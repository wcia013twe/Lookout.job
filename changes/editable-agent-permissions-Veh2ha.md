# Edit existing agent permissions

- Added an inline Edit permissions form to active connections under My Agent. Save/Cancel preserves unselected access, token, ID, name and expiry. Saved changes are read back before confirmation; account changes discard late responses. Revoked/expired connections remain uneditable.
- Added human-only connections.permissions through the existing authenticated gateway and service-only management RPC. Updates lock the owned active row, validate supported nonempty scope sets and reject stale expectedScopes. No token is generated, exposed or extended; existing issuance/revocation/profile setup paths are preserved.
- MCP parity is a narrow read-only open_agent_permissions handoff (workspace:read), not an agent permission writer. Agents can direct users to the signed-in editor and refresh tool discovery afterward. Guides/version references (contract 115) and OpenWiki document this boundary and release limits.
- Demo edits use fictional connection records and reset on refresh. Desktop/mobile browser checks cover grant/removal, unchanged metadata, cancel, empty selection, concurrent edit rejection, expired connections, no external writes, reset and overflow. Screenshots were visually reviewed; the UI detector returned no findings.
- Added SQL coverage proving the same credential can write Network after a human grant and cannot after removal, while rejecting cross-owner, stale, malformed, agent, expired and revoked edits. Added scoped MCP transport/authorization and demo tests. Restored a missing readGuide import in an existing networking test exposed by the full suite.
- Validation: focused tests and the connection database scenario passed; catalog validation (158 roles), frontend typecheck and production static build passed (425 offline assets). Final npm test: 1,009 passed, 5 skipped, zero failures, including database scenarios.
- Limits: no real account permission was changed, no live token was tested, and no migration/gateway deployment is established by these local checks. The UI and scoped handoff must be released with the migration/gateway through the normal main workflow before hosted availability is claimed.
