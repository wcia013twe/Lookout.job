# Safe work-history entry edits

- Added the scoped `edit_work_experience` MCP tool and shared owned SQL transaction for appending, patching or removing one entry. Muse no longer needs to reconstruct the entire history for routine entry edits. Node remains the MCP access point and forwards this lightweight CRUD operation to Edge; no worker, new store or profile-wide routing migration was added.
- Exact profile timestamps fence entry positions and reject stale/repeated adds/removals. Other entries, unknown existing entry fields and unrelated profile facts remain intact. Changes invalidate verification; no-op updates preserve it. Updated agent instructions and incremented developerVersion.
- Added the browser adapter over the same SQL validator and an isolated memory-only demo operation. Demo tests cover add/edit/remove, preservation, stale rejection and fixture reset without account writes.
- Validation: 723 tests passed, including every database scenario and the new preservation/ownership/version/consent scenario; data validation (158 roles), frontend and Node runtime typechecks, production static export (55 pages, 393 offline assets), whitespace check. After integrating newer local-main prefill changes, all 17 focused work-history/prefill tests passed. Local Supabase security advisors at error level reported no issues.
- Docker integration passed with the actual task Node MCP, isolated Edge Runtime and real local Supabase: add/update/remove, preserved history/fields, immediate HTTP 409 for stale add/removal retries, matching read-back and shared browser RPC. Retained review profile was inspected read-only and its row hash remained unchanged. Disposable accounts/container/temp credentials were removed. Receipt: `backend/local/work-experience-proof.json`.
- Real transport testing exposed PostgREST’s retry loop for manually raised `40001`; this entry operation now uses `PT409`, with shared gateway error mapping and a regression test. Existing source migrations for other operations were not rewritten.
- Limits: not deployed to hosted services. Existing bulk website autosync/import behavior remains unchanged; only the new entry operation provides these preservation/version guarantees. The additive migration is installed in local Docker; shared Node/Edge source containers were not upgraded or restarted. This is an implementation/local-proof pass, not availability on the running shared MCP endpoint.
