- Fixed the production migration preview/apply to use explicit linked-project targeting, include reviewed older pending versions, and skip local Vault configuration. The previous production release stopped in dry-run because four older migrations were absent after newer audit versions had shipped.
- Captured the observed 80-version Lookout hosted history as a test fixture. The full upgrade regression applies its pending migrations and compares columns, constraints, indexes, views, triggers, RLS, policies, table grants and function definitions/execute grants with a fresh source replay. It checks unchanged fictional profiles/connections and exercises import updates, Discover removal, connection ownership, profile revision checks and search workflows after upgrade.
- Added a forward migration revoking direct PUBLIC/anon/authenticated execution of the optional hosted RLS event-trigger helper. Its function and DDL hook remain intact. Historical hash differences in four migrations were statement separators, not conflicting SQL; no migration history is reset or rewritten.
- Hosted preflight found zero accounts/files, six shared companies, one knowledge configuration row and matching Storage bucket settings. A private preflight snapshot is retained under the task checkout's Git metadata; no personal local records/files are copied. This release does not enable workers, schedules or application submission.
- MCP mapping: existing scoped operations only; no new product action, service or tool. The source/current-hosted order is covered together with website/SQL and agent dispatch paths. Existing fictional demo fixtures remain detached; their isolation tests passed in the full suite.
- Validation: `npm test` (1,007 passed, 5 skipped, including exact hosted upgrade and database scenarios); `npm run validate:data` (158 roles); `npm run build` (425 offline assets); `git diff --check`; installed CLI help confirms all deployment flags. Initial hosted advisors identified the helper's unnecessary anonymous grant; the other authenticated definer RPCs are intentional owner-checking entry points.
- Release verification limit at commit time: schema/functions are not yet promoted. Main-branch production workflow, source/schema comparison, permission/advisor checks and disposable hosted smoke verification must succeed before reporting hosted readiness. Google OAuth, personal-data migration, GCP Node execution and real employer actions are outside this pass.
