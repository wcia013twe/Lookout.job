## What this comparison measures

Both conditions receive identical prescribed task requests, released source evidence, resume and explicit durable-output obligations. Baseline keeps persistent files; Lookout uses native scoped records, full native startup and on-demand discovery, including audit/change-feed capabilities. All native discovery, reads, writes, verification and failures count. The pinned participant is subscription-backed `gpt-5.6-terra`, medium; no paid API inference, silent model substitution, participant coaching or retries. Each pair runs baseline first on a dedicated fictional owner under an account lock.

This isolates the observed tool/storage workflow under prescribed requests. It does **not** measure reduced proactive user effort, real cognitive effort, open-web discovery, external sending or population effectiveness. One pair per case, fixed order, unblinded coordinator review and host/model variation prevent a general causal claim. A participant omission is an observed quality outcome, not automatically a product defect.

## Lookout changes flagged

1. **Complete the native audit assertion schema and return actionable validation errors.** All six failed COM04 audit writes omitted `scenarioId` in schema-version-2 assertion events. Offline validation reproduced the rejection. The discoverable generic event object does not fully expose the semantic requirements; the MCP response is only `Invalid tool arguments`. Improve schema/guide consistency and field-level feedback while preserving validation. This is a concrete product-contract weakness, not a missing scope, migration or harness permission.
2. **Investigate intake and commitment reconciliation.** An empty platform change feed must not stand in for checking newly supplied external evidence. COM04's missed promise supports reviewing the intake/save/verify workflow. The omission itself is a participant outcome; this pair does not prove a deterministic product bug or guarantee that a guide change fixes it.
3. **Investigate repeated discovery/context volume.** The measured native workload is substantial. Version-aware reuse and compact discovery are hypotheses to test prospectively, with quality retained. Do not remove native startup or audit obligations from the benchmark to make the numbers smaller, or attribute all additional execution time to audit.

No Lookout product change was made during these pilots. Harness repairs were prospective and did not rewrite historical grades.
