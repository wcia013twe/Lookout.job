## Current gaps that the design must not misrepresent

- Match percentages are fictional demo data; live catalog roles are unassessed. Preview contact edits are discarded. No scoring or live form-fill feature is established by those screens.
- Daily drop identity currently uses date/company/title and can collide. Proposed occurrences use a stable source key and keep location/URL evidence.
- Tracker/application dictionaries, network people/referrals and company records encoded as contacts are compatibility duplication. They are not separate target domains.
- Many profile fields already use named Markdown sections. Preserve that canonical document and strengthen its validator instead of building another writable SearchProfile schema. The current parser checks frontmatter/body length; complete duplicate-heading, typed-reference and source-dedupe validation is proposed work. Eligibility currently appears under About me while being profile-scoped: move shared authorization facts to country-keyed CandidateProfile, keeping availability preferences explicit. Current automation settings are instruction-backed; the proposed effective permission record must remain profile-specific and human-controlled.
- Interview debrief relationships currently hide inside artifact purpose strings. Proposed DocumentLink replaces this with typed FKs.
- Circles attachment files are local previews and must be removed before saving. Do not claim durable Circle file uploads. Shared context is a disclosed snapshot, not permission to query a private contact/application.
- Toolkit HTML practice answers reset on reopen. Persisted practice credit comes from Action Board, not the sandboxed artifact reader.
- Theme marketplace “saved” state lasts for the visit; it does not establish purchases or an installed theme service.
- Inference/reasoning belongs to users’ personal agents. The app exposes context and validated output writes; AgentTask is a handoff inbox and AgentCheckpoint is a sync cursor. No hosted inference engine or model metadata is required. Agent credentials, queued requests, routines and delivery preferences do not prove runtime/scheduler/channel capabilities. Demo CAPTCHA, email reconnect and outreach approval handoffs are not evidence those integrations are live.
- The static privacy page does not establish retention deadlines or a working self-service export/erasure workflow.

## Review scenarios

1. One job appears through two sources in two personal batches: one Job, distinct observations and owner/profile decisions; no cross-user fit leak.
2. A user opens, queues, edits and then reports applying: one Application; separate opened/queued/report evidence; no invented employer receipt.
3. A résumé is replaced: future assignments resolve to the new current version; old draft/attempt still opens its pinned bytes/title.
4. One person is contacted about two roles: one Contact, explicit conversation/application relationships; logging a reply does not advance either application stage.
5. A shared practice session serves two applications and a learning goal: one elapsed duration, three task credits; retries do not add time again.
6. A user shares a debrief, then edits private notes: the shared revision remains exactly what was disclosed. A newer unapproved post revision stays private.
7. A company-scoped saved answer has not resolved to the public registry: it remains company-scoped and never becomes global autofill.
8. A Circle member is removed and rejoins: an old invite cannot restore access; receipts can report withdrawn/unavailable source without exposing private references.

9. A user edits Career goals: only that section changes; unknown prose remains, and the new document version and derived projection commit together.
10. An agent saves company research: the Research UI loads one linked analysis body with sources and input versions; editing it never changes verified candidate facts or submission policy.
11. A simple source UI edits a name: provider/API/keywords, queries and filters survive even though the UI does not show them.
12. A newer profile or résumé exists: previous analysis remains readable and reports newer inputs; it is not silently rewritten.

These are design walkthroughs, not executed runtime tests of the proposed schema.
