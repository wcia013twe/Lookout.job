# Communication case readiness review

A case is ready to launch only after its implementation and isolated environment meet the checks below. Passing these checks is not a participant result. No participant should be launched merely to discover a missing tool or invalid fixture.

## Shared gate

- Versioned scenario, actor, grader, allowed tools, budgets and staged evidence are frozen together with actual executable source and container image.
- Fresh-session grouping and released-turn counts are explicit. Future events/answers are inaccessible; profile is given equally at onboarding, resume remains available, baseline persistence is agent-created.
- A private parity receipt verifies complete profile facts and resume equivalence between native state and readable initial prompt; no unannounced extra native preferences. Each turn exposes the same explicit scenario clock to both conditions.
- Each case owns a dedicated fictional local account, authenticated server-side case marker and lock. No real owner or another case may be reset. Both conditions start from equivalent facts.
- Actual scoped writers have passed a separate save/read smoke on that owner, including the precise fields/provenance required by the case. Fixture restored afterward. Listing schemas alone is insufficient.
- Subscription login, container isolation, read tools and equal evidence tools pass preflight without inference.
- Observable quality checkpoints require saved-state/file evidence where persistence is required. Acknowledgement is not evidence of understanding and is not a failure when no specific response is requested.
- Final reconciliation and after-run independent reads follow com-final-state-grading.md. Pre-final continuity and post-final corrections remain distinguishable. Historical snapshot/receipt bindings prevent later account reuse from changing the grade.
- Grader cannot send, modify state, help the participant or read future evidence during execution. Missing required telemetry is an invalid verification result, not zero effort or assumed outcome failure.
- Metadata-only Langfuse mapping/register/readback is verified; private messages/profile/resume remain local. Synthetic smoke and pilots are labelled and excluded from measured results.
- Independent reviewer checks actual packets, feasible alternatives, temporal consistency and rubric applicability. Known limits remain in the case report.

## Case-specific acceptance

### COM2

Application communication only; no interview prep/forms/sends. Distinguish user-reported submission/completion from employer evidence. Represent rescheduling, explicit rejection, cancellation and obsolete reply retirement using supported records. Do not require unsupported application status writes. Baseline and Lookout can satisfy semantic state equally. One appointment in email/calendar is not two interviews.

### COM3

User approved fixed searchable fictional sources. Verify deterministic content-based search, pagination, equal per-session budgets and release-gated source reads even when future IDs are guessed. At least two evidence-supported final candidates, clear opts-out, current versus archived affiliation, truthful profile hooks and no invented referral authority. Reference alternatives stay private. Source prose must not contain grader advice, candidate suitability labels or personalized answer hints. Every supplied source link must be resolvable through the controlled reader. Report controlled discovery, not open-web coverage or hiring improvement.

### COM4

User approved an overdue promise. Include enough explicit simulated time and a dated commitment to distinguish premature from overdue follow-up; no actual send. Explicit user-reported sends bridge bio/availability drafts to observed replies. Introduction fulfills original commitment; meeting scheduling is separate from meeting completion. Verify actual supported ongoing-interaction storage rather than invented fields. Derived UI waiting labels must not force fabricated messages to satisfy a semantic state check.

## Launch handoff

Record case/version, sessions/turns, source commit and retained checkout, private frozen root, dedicated-owner verification, writer-smoke/restore receipts, preflight receipt, grader checks and exact launch command. Surface unresolved design choices before claiming ready. No paid model API is needed: participant runs use the pinned subscription Terra medium configuration. Fail loudly and preserve attempts; no participant rescue or silent retries.
