# MCP Events

The existing Node `/mcp` endpoint supports `events/list`, `events/subscribe`, and
`events/unsubscribe`, advertised in `initialize.capabilities.events`. The Edge MCP
endpoint does not advertise events. The implementation follows the current
[OpenAI MCP Events protocol](https://developers.openai.com/plugins/build/mcp-events)
(read November 10, 2026).

`lookout.work_available` accepts empty arguments and emits only a change ID and
kind from the existing system Muse feed. Both `workspace:read` and `activity:write`
are required, matching the existing watch boundary. It neither performs work nor
acknowledges it. On wake, the consumer reads `read_muse_changes`, fetches current
records, performs authorized work, and acknowledges only handled IDs. Existing
submission, approval, scope and idempotency checks remain authoritative.

Subscriptions are per connection, deterministic and private, with at most ten
per connection. Default/maximum lifetime is one day, capped by connection expiry;
`ttlMs` requests shorter lifetimes. Null TTL still grants a finite lifetime. There
is no replay cursor: events predating a subscription must be read from the existing
pending feed. The supplied signing key is validated, never generated by Lookout.
Signed verification uses a fresh challenge, constant-time comparison and a
five-minute cache bound to connection, URL and key. Rotation signs with both keys
for five minutes. Secrets remain in private RLS-enabled tables, inaccessible to
anonymous and authenticated database clients.

HTTPS callbacks use connection-time public IPv4 selection and socket pinning,
original-hostname TLS verification, ten-second timeouts, bounded response bodies,
and no redirects. IPv6-only destinations fail closed in this version. Every
request uses Standard Webhooks HMAC SHA-256 over the exact serialized body.

Activity inserts enqueue deliveries transactionally. The existing Node API listens
for the existing Supabase Realtime workspace invalidation hints and drains the private outbox on startup,
reconnect and new work. Timers run only for outstanding deliveries or bounded
failure recovery; no polling worker is added. The existing `supabase_realtime`
publication of `workspace_changes` must be available. This feature changes neither
that publication nor existing grants/policies. Realtime never publishes subscription
keys, activity bodies or delivery rows.

Database leases coordinate API instances. Retries preserve event IDs, use fresh
signatures, exponential backoff and at most six attempts. `410` removes the
subscription; `413` and other permanent client errors terminate that delivery.
Every delivery rechecks connection expiry, revocation, scopes and subscription TTL.
A lost response can cause duplicate receipt, so the consumer must deduplicate by
`eventId`. Delivery receipts never consume the work feed. Exhausted delivery or
prolonged infrastructure outage leaves work in that feed for recovery.

## Activation and verification limits

Production Node endpoint: `https://34-148-155-27.sslip.io/mcp`. It uses the existing
opaque `jb_agent_` bearer credential. No credentials, OAuth setup, service identity
or account grants are changed here. Current ChatGPT plugin authentication does not
support presenting that custom API key, and the live endpoint does not offer OAuth
metadata/challenges. Consequently source support or deployment is **not** evidence
of active dot wakeups. The next scope decision is an explicitly authorized,
host-compatible authentication integration; do not copy local tokens or silently
replace authentication. After that, connect/rescan the plugin, subscribe through
the host, verify the signed challenge, produce real work, and verify both webhook
2xx receipt and the dot run before retiring any existing watcher.

Deploy the migration through the existing main-branch Supabase workflow, then
release the tested Node commit through `scripts/deploy-gcp.mjs`. Do not deploy a
feature branch. Keep existing services and watcher settings until the full host
subscription is verified. The detached demo's `readMcpEventPreview` illustrates
notification pointers without real callback traffic or persistent account storage.
