# JOB03 independent final grader

Review only after both condition attempts terminate. You must be a fresh agent
with no inherited chat context and must not have implemented, coordinated,
operated or participated in either attempt. Coordinator records your actual agent
identity and an exclusion roster; attest to fresh context and all four exclusions.
The shell checks assignment/attestation, not independently provable agent history.

Read the frozen scenario, fixture, public run artifacts and terminal confirmation
receipts. Do not receive credentials, change records, run a participant, repair
work or send anything. Checkpoint `after.json` is authoritative durable evidence;
participant responses and promises are claims to cross-check. A failed receipt is
not proof of a participant failure; flag unavailable verification explicitly.

For each reached checkpoint and each condition, extract `jobs` in the fixture's
semantic format with every field and logical reminder key. Cite that checkpoint's
`after.json` plus concrete trace/file paths as needed in `evidenceFiles`. This
normalization does not require baseline to use a native schema. Compare all five
jobs, including E's untouched blocker/reminder and the entire duplicate checkpoint.
History uses the frozen logical event IDs, once each, in chronological order;
retain the distinction between user report and employer evidence. No validated
submission receipt exists. A correct final repair cannot erase an earlier error.

Rate each `quality` key at every reached checkpoint: 0 unmet/contradicted, 1 partial
or material gap, 2 fully supported. For inapplicable event-specific criteria,
correct preservation is the expected behavior. Include `reason` and frozen
`evidenceFiles`, including the checkpoint's durable `after.json`. Check routing,
B's saved answer and only B's cleared blocker, unsubmitted B, A's user-reported
submission, C's withdrawal, D's sourced rejection, obsolete actions cancelled,
history preserved and E untouched. Check pending obligations and final report
against saved state. Do not grade an unobserved state as guessed success.

Reminder quality requires actual captured scheduling/readback receipts, exact
November 18 09:00 America/New_York = 14:00Z due time, one real test-channel delivery
and replay/cancellation evidence. Notes saying "remind" cannot substitute. Delivery
must not send to an employer or ordinary user's channel. An adapter's promise is
not a scheduler receipt. Lookout native usage is separate diagnostic adherence:
`met`, `unmet`, or `unreached`, with evidence. Do not add native requirements to
baseline quality. Count unique interactions once even across categories; scripted
initiations and simulated waiting are separate from actual effort and execution.
Read-only terminal native and baseline-file confirmation occur after timing ends.

Submit `{attestation, conditions:{baseline:{reviewer,extraction,checkpoints},
lookout:{reviewer,extraction,checkpoints,adherence}}}`. `extraction[stage]` contains
`{jobs,evidenceFiles}`. `checkpoints[stage][qualityKey]` contains
`{rating,reason,evidenceFiles}`. Attestation contains `reviewer`, `assignmentHash`,
`freshContext:true`, and `didImplement/didCoordinate/didOperate/didParticipate:false`.
Preserve failed/time-limited trajectories; do not rescue, retry or infer unreached
checkpoints. A partial attempt is reportable as partial_review, not a full pass.

For `interrupted_preparation_recovery`, verify the one actual injected B preview
timeout in tool evidence and its saved name/email fields, unresolved start-date
blocker, later answered/cleared blocker, then a fresh-session continuation of the
same application. There must be exactly one controlled failure, one application,
retained completed fields and no submission/validated receipt. The answer turn
alone must not prematurely finish preparation. Check the historical failure and
recovery at their own checkpoints; final success cannot erase lost progress.
