Implementation scope · November 12, 2026

Save feedback. Let your agent interpret it.

One compact helpful/not-helpful control for collected jobs, analyzed jobs, networking recommendations, and weekly planning items.

Lookout owns capture

  • Private Supabase records.
  • Optional reason and note.
  • Edit, clear, and confirmed readback.
  • Scoped MCP reads of new and changed feedback.

Your agent owns learning

  • When to read the log.
  • How to interpret feedback.
  • Where to maintain its memory.
  • Whether to change future recommendations.

Timing: save now, review before the next batch

Saving never starts inference. The external agent can read incremental feedback before making more recommendations. An end-of-day or weekly roundup is an optional host policy, not a Lookout schedule.

No scheduler, automatic preference changes, or improvement guarantee is included.

Budgets apply to the backend—not inference

100 targets per read · 100 changes per page · 60 fresh writes per account per rolling minute. Optional reasons allow 200 characters; notes allow 2,000 characters; supplied context allows 8,192 bytes.

There are no model-token or dollar budgets because Lookout does not own those model calls. No total-storage quota or automatic retention cleanup is included. Clear withdraws current feedback; private history can retain earlier notes.

Safety and release checks

  • Account boundaries and expected revisions protect saves.
  • Incremental readers see edits and withdrawals, not just first ratings.
  • Helpful does not mean Apply, Send, Approve, or Done.
  • Demo stays fictional and cannot write real feedback.
  • Schema and backend deployment are required before hosted persistence is available.
