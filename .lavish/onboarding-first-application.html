Design notes · scope, reuse, and edge states

The smallest useful journey

Keep the existing connection screen. Once the agent confirms its runtime, ask for a search direction, reveal one verified role, then offer preparation. Reuse existing context; ask for a résumé or missing answers only when preparation requires them. The user can leave after the work is queued.

The card is the first-value moment

Reuse the existing card surface, selected pack style, reveal animation, keyboard/swipe behavior and reduced-motion handling from next-app/components/pack-opening.tsx. Extract its private RevealCard for reuse during implementation. Onboarding advances directly from the back to the final role in one gesture. No tier-up ladder, XP claim, multi-card pack or repeated celebration. A plain “Show role directly” path remains available. Reveal never controls application authorization or whether a time-sensitive opportunity is captured.

Approval is a separate, quiet interaction

A connected-app message opens an authenticated review of a specific application revision, including the exact résumé and employer answers. The explicit approval applies only to those materials and one employer. Changes invalidate approval. No bare “yes” text is treated as authorization. Unsupported submission routes hand off to the employer form; the interface shows Applied only after a validated receipt.

What is real today

The connection UI, first-match onboarding contract, revision checks, queued tasks, demo isolation, preparation policy, and card reveal exist. Notification delivery and automatic submission are not verified live. This prototype proposes those handoffs; its “simulate” actions are review controls, not product actions.

Reuse and implementation mapping

Keep AgentConnections; evolve AgentFirstSetup and onboardingWork; reuse the application document preview and existing scoped onboarding/task operations. Match receipt, preparation, notification and submission remain distinct states. A ready notification and final submission must use capability-checked, narrowly scoped service/MCP paths with the same ownership and version validation. Never mark onboarding task completion as employer submission.

Branches that keep the experience honest

  • No match: offer a single refinement and let the user leave while search continues. Never reveal a placeholder as a real role.
  • No résumé: request one at preparation, while allowing recommendations without it.
  • Missing employer answer: ask only that question; never guess. Then reopen review.
  • Notification unavailable: show the ready application in the workspace, with an explicit delivery gap.
  • Outcome uncertain: show “Confirming submission,” never “Applied”; prevent a blind retry until the outcome is resolved.
  • Decline the role: ask one optional reason and find another; retain previous context.
  • Returning user: resume the authoritative current state without replaying setup or card ceremony.

Recommendation

Make preparation the primary offer after the reveal, with “Just find roles” beside it. Keep automatic submission policy, notification schedules, social setup and feature tours out of this first experience. User success is a useful first role and a clear next action, even if they never apply during onboarding.

Visual direction inherits Lookout’s existing Inter typography, dark setup palette, lavender actions, 8–16px corners, and purple card reveal. This is a self-contained interaction design; production React code is unchanged.
